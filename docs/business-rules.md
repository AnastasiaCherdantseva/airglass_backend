# Бизнес-правила

## Создание сессии

- **BR-AUTH-001.** При каждой успешной авторизации создаётся новая сессия.
- **BR-AUTH-002.** Наличие других активных сессий не препятствует новой авторизации.
- **BR-AUTH-003.** Один пользователь может иметь несколько активных сессий одновременно.
- **BR-AUTH-004.** Сессии не ограничиваются по устройству или IP-адресу.
- **BR-AUTH-005.** `user_agent` — необязательный параметр сессии.

## Жизненный цикл

- **BR-AUTH-007.** При активности пользователя `expires_at` сессии продлевается.
  - **BR-AUTH-007.1.** Продление выполняется не чаще одного раза в 24 часа: если с момента `last_used_at` прошло меньше суток, продление не выполняется.
  - **BR-AUTH-007.2.** Если `last_used_at` отсутствует, продление выполняется сразу.
  - **BR-AUTH-007.3.** Продление выполняется на 7 дней от текущего момента.
  - **BR-AUTH-007.4.** Источник истины для продления — данные в БД, не cookie клиента.
- **BR-AUTH-008.** Logout делает текущую сессию недействительной и удаляет её.
- **BR-AUTH-009.** По истечении срока сессия становится недействительной.
- **BR-AUTH-010.** Потеря cookie не удаляет сессию из БД.
- **BR-AUTH-011.** Отсутствие cookie = пользователь неавторизован.
- **BR-AUTH-012.** Токен сессии передаётся клиентом в cookie.

## Деактивация пользователя

- **BR-AUTH-013.** При `is_active = false` создание новых сессий запрещено.
- **BR-AUTH-014.** При деактивации активные сессии удаляются.

## Смена пароля

- **BR-AUTH-015.** При смене пароля все сессии отзываются, кроме текущей.
- **BR-AUTH-016.** Если текущую определить невозможно — отзываются все.

## Frontend

- **BR-AUTH-017.** Авторизованный не имеет доступа к странице логина.
- **BR-AUTH-018.** Проверка авторизации на бэкенде обязательна.
